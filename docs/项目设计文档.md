# Knot 图片分享应用 - 项目设计文档

## 一、软件定位

### 1.1 项目概述

**Knot** 是一款基于鸿蒙操作系统（HarmonyOS Next）开发的图片社交分享应用，致力于为用户提供一个优质的图片内容创作、分享和社交平台。用户可以通过应用发布图片作品、发现精彩内容、关注感兴趣的创作者，并通过点赞、收藏、评论等方式进行社交互动。

### 1.2 目标用户

- 摄影爱好者：分享摄影作品，展示摄影技巧
- 生活记录者：记录生活中的美好瞬间
- 创意设计师：展示设计作品，获取灵感
- 内容消费者：浏览精美图片，发现优质内容

### 1.3 核心价值

- **内容为王**：以高质量图片内容为核心，打造视觉盛宴
- **社交连接**：通过关注、互动机制连接志趣相投的用户
- **简洁易用**：采用瀑布流设计，提供流畅的浏览体验
- **原生体验**：基于鸿蒙原生开发，提供卓越的性能和体验

### 1.4 产品定位

**"发现生活，分享精彩"** - 一款轻量级的图片社交应用，专注于图片内容的创作与分享，为用户提供沉浸式的视觉体验和活跃的社区氛围。

- 支持下拉刷新和上拉加载更多
- 图片懒加载，优化内存占用

#### 4.2.2 安全要求

- 密码采用加盐哈希存储
- API接口采用JWT Token认证
- Token过期自动跳转登录页
- 防止SQL注入、XSS攻击
- 敏感信息不在前端暴露

#### 4.2.3 用户体验

- 遵循鸿蒙设计规范
- 提供加载状态提示
- 操作结果即时反馈（Toast提示）
- 支持手势操作（下拉刷新、滑动返回）
- 空状态友好提示

#### 4.2.4 兼容性

- 支持HarmonyOS Next API 12+
- 适配不同屏幕尺寸
- 支持深色模式（部分支持）

## 六、功能设计

### 6.1 用户注册与登录

#### 6.1.1 功能流程说明

**注册流程：**
1. 用户输入注册信息（用户名、密码、真实姓名、手机号、邮箱）
2. 前端验证后提交注册请求
3. 后端验证唯一性、密码加盐哈希存储、生成用户ID
4. 返回注册成功

**登录流程：**
1. 用户输入用户名和密码
2. 后端验证并生成JWT Token
3. 前端存储Token并跳转到主页

#### 6.1.2 时序图

```mermaid
sequenceDiagram
    participant U as 用户
    participant V as LoginPage
    participant VM as AuthViewModel
    participant API as UserApi
    participant S as 后端服务

    U->>V: 输入用户名密码
    U->>V: 点击登录按钮
    V->>VM: handleLogin()
    VM->>VM: 数据验证
    VM->>API: login(username, password)
    API->>S: POST /api/v1/auth/login
    S->>S: 验证用户名密码
    S->>S: 生成JWT Token
    S-->>API: 返回Token和用户信息
    API-->>VM: 返回登录结果
    VM->>VM: 保存Token到TokenManager
    VM->>VM: 更新登录状态
    VM-->>V: 通知登录成功
    V->>V: 更新AppStorage状态
    V->>V: 清空导航栈，返回主页
    V-->>U: 显示登录成功提示
```

### 6.2 发布帖子

#### 6.2.1 功能流程说明

1. 用户进入发布页面，输入标题、描述（可选）
2. 选择1-9张图片，添加标签（可选）
3. 前端读取图片文件并构建multipart/form-data格式
4. 提交到后端，保存图片、创建帖子记录、处理标签
5. 返回主页并刷新列表

#### 6.2.2 时序图


### 6.3 发现页与帖子详情

#### 6.3.1 功能流程说明

**发现页流程：**
1. 加载帖子列表，以瀑布流形式展示
2. 支持下拉刷新、上拉加载更多
3. 点击帖子卡片进入详情页

**帖子详情流程：**
1. 并发请求帖子详情、收藏状态、点赞状态、关注状态、评论列表
2. 展示图片轮播、内容信息、作者信息
3. 支持点赞、收藏、评论、分享操作

## 七、亮点设计

### 7.1 MVVM架构模式

**设计理念：**
- 采用标准的MVVM架构，实现UI层与业务逻辑的完全解耦
- Model层：定义数据结构（Entity）
- Service层：封装API调用和数据存储
- ViewModel层：处理业务逻辑、状态管理、数据验证
- View层：专注于UI渲染和用户交互

### 7.2 HTTP请求封装

**设计特点：**
- 统一的请求封装，支持JSON和multipart/form-data
- 自动添加认证Token到请求头
- 统一的响应格式处理
- 完善的错误处理机制
- 支持Token过期自动跳转登录

### 7.3 瀑布流布局

**实现方式：**
- 使用HarmonyOS的WaterFlow组件
- 双列瀑布流展示，自适应图片高度
- 根据图片原始宽高比计算显示高度
- 支持下拉刷新和上拉加载更多
- 平滑的滚动体验

### 7.4 状态同步机制

**设计方案：**
- 使用PostStateManager管理帖子状态（点赞、收藏）
- 从详情页返回时自动同步状态到列表页
- 使用AppStorage实现跨页面状态共享
- 支持登录/退出登录的全局状态更新

### 7.5 并发请求优化

**设计思路：**
- 在帖子详情页，使用Promise.all并发请求多个接口
- 同时获取帖子详情、收藏状态、点赞状态、关注状态、评论列表
- 减少页面加载时间，提升用户体验

### 7.6 图片预览功能

**功能特性：**
- 点击图片进入全屏预览
- 支持图片轮播和缩放
- 支持手势滑动切换图片
- 下滑关闭预览
- 流畅的过渡动画

### 7.7 分享功能设计

**设计亮点：**
- 支持多种分享方式（应用内分享、外部分享）
- 动态生成分享卡片预览
- 支持分享给互关好友
- 分享记录持久化存储（设计已完成）

## 八、可能存在的问题

### 8.1 性能问题

#### 8.1.1 图片加载性能

**问题描述：**
- 瀑布流一次性加载过多图片可能导致内存占用过高
- 大图加载慢影响用户体验
- 没有图片缓存机制

**解决方案：**
- 实现图片懒加载机制
- 使用缩略图代替原图
- 实现图片缓存策略（内存缓存 + 磁盘缓存）
- 对超大图片进行压缩处理

#### 8.1.2 列表滚动性能

**问题描述：**
- 长列表滚动可能出现卡顿
- ForEach渲染大量数据性能下降

**解决方案：**
- 使用LazyForEach代替ForEach
- 实现虚拟滚动
- 限制每页加载数量
- 优化图片渲染

### 8.2 数据一致性问题

#### 8.2.1 点赞数同步问题

**问题描述：**
- 多个用户同时点赞，可能导致点赞数不一致
- 前端显示的点赞数与后端实际数据不同步

**解决方案：**
- 后端使用事务和乐观锁保证数据一致性
- 前端定期刷新获取最新数据
- 使用WebSocket实现实时同步（后续优化）

#### 8.2.2 状态同步延迟

**问题描述：**
- 从详情页返回列表页，状态更新可能有延迟
- 跨页面状态同步不够实时

**解决方案：**
- 使用PostStateManager统一管理状态
- 利用页面生命周期onPageShow同步状态
- 考虑引入响应式状态管理库
